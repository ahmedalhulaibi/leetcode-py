Every problem directory includes `playground.py`, a scratchpad for poking
at inputs, inspecting data structures, and experimenting before you commit
to an approach. See [Problem Anatomy](/practice/problem-anatomy) for where
it fits.

## Percent format, not .ipynb

Playgrounds are stored as jupytext **percent format**: plain Python with
`# %%` cell markers.

```python
# %%
from helpers import assert_two_sum, run_two_sum
from solution import Solution

# %%
# Example test case
nums = [2, 7, 11, 15]
target = 9
expected = [0, 1]

# %%
result = run_two_sum(Solution, nums, target)
result

# %%
assert_two_sum(result, expected)
```

In git that means clean diffs, real code review, and mergeable history,
with none of the JSON noise `.ipynb` would add.

## Open it as a notebook

Pick whichever fits your setup:

- **VS Code**: the Python extension supports `# %%` cells natively; open
  `playground.py` and run cells in the interactive window.
- **JupyterLab with the jupytext contents manager**: same experience, in
  the browser.
- **One-off conversion**: `uv run jupytext --to ipynb
  leetcode/two_sum/playground.py` gives you a real `playground.ipynb`.

## Convert back before committing

If you converted to `.ipynb`, convert back before you commit. The repo
keeps only the `.py` form:

```bash
bake nb-to-py   # all .ipynb under leetcode/ -> py:percent, .ipynb deleted
```

## Generate marimo notebooks

Run from the repository root:

```bash
uv run scripts/gen_marimo.py                       # all problems
uv run scripts/gen_marimo.py leetcode/two_sum      # one problem
uv run --with marimo==0.25.2 marimo edit --sandbox --headless leetcode/two_sum/playground_marimo.py
```

The script builds an unfinished exercise from the problem's JSON template,
then uses Jupytext and [`marimo convert`](https://docs.marimo.io/guides/coming_from/jupyter/#convert-python-scripts-to-marimo-notebooks)
to write `playground_marimo.py`. Each notebook includes the statement, examples,
constraints, unfinished solution methods, a **Run tests** button, and notes.
Inline metadata installs the local SDK with its practice dependencies.
Generated notebooks can be committed to Git and are skipped on later runs to
preserve your edits. Use `--force` to replace them, or `--jobs N` to set concurrency
(default: 8). Conversion failures are reported and produce exit status 1.

## Start the local server

```bash
cd "$HOME/workspace/va/leetcode-py"
bash scripts/start_marimo.sh
```

The launcher starts headless from this repository and serves only its notebooks
at <http://127.0.0.1:2718>. It does not open a browser. Each notebook runs in a
sandbox with its own dependencies.
Open the [NeetCode index](http://127.0.0.1:2718/?file=neetcode.py) for NeetCode 150,
250, or All. Search the table, select a row to read the statement, then use
**Open notebook** to start the problem playground in a new tab.

Implement the **Your solution** cell in the notebook, then press **Run tests**.
The runner executes the full `test_solution.py` bank in a separate process
against your current notebook implementation. It does not import the adjacent
reference `solution.py` or replace source files. Add Markdown cells for notes.

Running `pytest` directly on the original problem folder checks the supplied
reference solution; use the notebook button to check your notebook code.

Stop the server with Ctrl+C, then confirm the exit prompt.

## A scratchpad, not the contract

The original Jupytext `playground.py` imports the supplied reference solution.
The marimo `playground_marimo.py` uses your unfinished implementation instead.
Both use the same [test_solution.py](/practice/testing) contract.
